# Memory curve

- The chart uses a fixed 420 × 150 viewBox and fits its container (maximum 640 px). Calendar days and review count never increase its intrinsic width. The vertical scale stays at 0–100%.
- Horizontal positions preserve real local-calendar intervals: `(date - first displayed review) / (forecast end - first displayed review)`. Dates are not equally spaced review events. A single recorded date never invents an earlier learning date.
- The default view contains the last eight recorded review dates. Show all changes only the displayed range and retains the same chart width. Same-day entries are merged as before. No storage or scheduler policy changes; all means all records currently available, not previously discarded history.
- Today is labeled literally `Today`, rather than as another date. It has a vertical marker and a model-estimated retention point. Review dates near that label or each other omit their axis text, but remain in their correct positions and can be inspected by pointer/touch or keyboard.
- The past modeled curve is solid through Today. The future segment starts at the exact same coordinate and is dashed. Its endpoint is hollow. Neither the curve nor its endpoints are measured probabilities; FSRS provides estimates. No future review or grade is fabricated.
- The forecast range includes the next due date/fallback interval and at least tomorrow, including overdue cards. The endpoint is a prediction-horizon point, not an additional scheduled review. Existing due dates and FSRS state are unchanged.
- Date markers rebuild after local midnight and when a workspace/window regains focus or visibility. Each view owns its timer and listeners; closing/unloading releases them. Browser cards request fresh HTML from the local bridge, and reject cached curves dated yesterday. Offline refresh keeps the last received chart rather than inventing fresh data.
- Obsidian and Web use the same typed controls in `src/curve-controls.ts`; `pkg/browser-extension/curve-controls.js` is generated, not a second hand-maintained implementation. HTML is generated by the same view builder, and Web uses isolated card styling.
- No draggable guide-only chart size was added. The user plans to author the guide as Markdown with screenshots; connecting that file still needs its path.

## Checks

`npm test` covers date ratios, invariant width, Today splitting, last-eight/all ranges, single-date/future/invalid state and unchanged data. `npm run test:curve` covers 260/380/720 px, light/dark, native and Shadow DOM controls, point inspection, keyboard use, day refresh/cache expiry and cleanup. `npm run test:settings-layout` and `npm run test:browser-shadow` check existing integrations. These isolated checks do not replace user-operated Obsidian/mobile acceptance.

## Inline syntax for the user-authored guide

Use the configured entry and alias delimiters; the defaults are `::` and `/`:

```md
## People
Theseus / Captain {Pilot} :: Captain of the ship.
```

This is one inline entry named Theseus, with Captain as an alias and Pilot as a color token. Space around `/` is optional. The entry file must be configured as an inline dictionary source. Heading classification follows the configured heading level and nested heading path; color tokens refer to configured entry colors or direct supported colors. The current parser uses one line per entry; a following line is not automatically appended to its annotation. A literal alias delimiter in a name can be escaped with a backslash.
